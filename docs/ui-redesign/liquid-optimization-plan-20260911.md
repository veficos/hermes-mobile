## 一、结论与边界

当前处于“组件体系已有基础，整页设计与交付验收尚未收敛”的阶段。
不能用一个还原度百分比描述差距：代码覆盖、视觉相似和设备体验是三种不同指标。

“iOS 26.6.0”作为用户指定的视觉目标；本轮没有该具体版本的可核验官方
参考图、SDK 或真机对照，不能虚构版本专属样式及参数。推荐交付目标是
符合 Liquid Glass 层级、清晰度与交互连续性的跨端产品，而非像素级原生复制。

Flutter Web 与当前 iOS 工程都使用 Flutter 材质：背景模糊、染色、连续圆角、
模拟高光；没有真实折射或原生玻璃视图。原生桥接/shader 是独立可选研究。
本轮没有可靠完成逐张整页视觉审阅，以下视觉问题属于待确认风险，不冒充
截图中已观察到的缺陷。

## 三、统一视觉规则

1. 四层结构：连续页面底色 → 稳定内容平面 → 玻璃导航/操作 → 模态弹层。
2. 一个表面只拥有一套 blur/tint/highlight；正文、代码和终端不逐块模糊。
3. 导航强调透景连续性，控件强调可点击性，弹层强调前景优先级。
4. 浅色校准轮廓与白底区分；深色校准文字与边缘，避免只靠增强白色高光。
5. 延用已实现的手机 17/14 排版，不机械放大桌面；间距收敛到 4/8/12/16/24/32。
6. 页面边距建议手机 16–20；头像框建议 44–48；控件有效点击区至少 44×44。
7. 图标视觉尺寸与点击区分离；短行居中，多行内容按稳定文字起始线对齐。
8. 普通正文复合背景对比度至少 4.5:1，非文字关键控件轮廓目标 3:1；
   状态不只用颜色表达。禁用状态需要单独审阅，不能统一降低透明度了事。
9. 动效表达按压、选中、展开与层级，不为每次 token、加载或历史合并播放入场动画。
10. 保留 Classic 默认值、四配色与用户偏好；减少透明度时层级仍靠底色和轮廓成立。

以上为产品设计建议，不是 Apple 官方版本常数。

## 四、逐页优化范围

### 聊天：第一优先级

- 正文、工具摘要、内联审批共用阅读网格；保留用户/助手区分，不强制气泡等宽。
- 统一输入框、附件、引用、操作按钮外壳；确保键盘、安全区和三栏变化不遮内容。
- 历史顶部区分加载、错误重试和已到开头；读历史时新消息提示不抢滚动位置。
- 等待首 token 与实际流式输出分开反馈；收到文本及时展示，不用人工逐字动画掩盖缓冲。
- 审批明确待处理、提交中、通过/拒绝、失败/过期；避免重复提交，保留结果。
- 审批主按钮清晰，范围扩大的授权单独说明；不为美观隐藏权限边界或自动授权。
- 校验长 Markdown、代码、图片、工具详情、错误和离线状态，不只审查纯文本聊天。

### 机器人：选择效率优先

- 保留已合并的概览与“管理Bot”入口；不再创建第二套中心卡片。
- 首屏突出名称、用途与开始聊天；诊断、服务、模型等细节逐层展开。
- 统一头像裁剪/占位、名称列与尾部菜单；长名称、大字与徽章不争抢宽度。
- 区分当前选中、置顶、在线和运行中；仅展示影响选择的少量状态。
- 用真实头像验证加载/失败/透明图/极端长宽比，检查列表到详情的识别连续性。

### 任务：降低信息和手势冲突

- 搜索、筛选、视图切换、新建形成稳定工具区；窄屏允许有序换行。
- 标题第一层，状态/优先级第二层，负责人/评论第三层；减少标签争夺注意力。
- 手机推荐列表但尊重用户偏好；看板提示横向还有内容。
- 明确横向看板、列内纵向滚动与刷新边界；批量操作不覆盖导航/安全区。
- 无任务与筛选无结果分开；移动、失败、重试与返回状态完整保留。

### 更多、设置和次级页面：统一低频操作

- 延用分组目录与已实现搜索别名；统一图标容器、行高、分隔线起点与尾部箭头。
- 审核重复状态和入口，危险操作与普通设置分组，不靠更多彩色卡片分层。
- 外观预览包含真实导航、阅读区、输入框与弹层；对照实际页面而非孤立材质块。
- 文件、Git、编辑器、通知、终端统一返回/保存/取消、未保存提示和关闭焦点。
- 文件栏扩大点击区后检查长文件名、展开层级及 Tab/Enter 操作；当前尺寸测试
  通过不能替代键盘及屏幕阅读器验收。

## 六、验收矩阵与性能预算

- 视口：320/390/430、768/900、1280；桌面含填充内容的真实三栏，不仅空壳。
- 外观：明暗、四配色、1x/2x 文本、减少透明度/动画、高对比；3x 按风险补测。
- 内容：长名称、双语/RTL、真实头像、Markdown、代码、图片、工具及审批。
- 滚动：持续拖动、连续十页、延迟/失败重试、流式更新、媒体变高变矮、
  窗口裁剪、切换会话、键盘和侧栏开关。用户无主动滚动时，同一消息锚点
  受控布局变化目标漂移 ≤2 逻辑像素，并检查中间帧；主动拖动不套用静止阈值。
- 交互：Tab 顺序、Enter/Space、Escape、弹层焦点返回、VoiceOver、可点击尺寸。
- 性能：Release 固定设备/OS/浏览器/渲染器与数据量，记录 UI/raster p50/p95、
  慢帧比例及样本数。60Hz 对照 16.7ms，120Hz 另测 8.3ms；Web 用浏览器工具
  补充合成器证据，无可用 Flutter 样本不能填零。最终预算在 P0 设备基线确认。
- 优化顺序：减少模糊区域与独立表面 → 减少不必要重绘 → 校准动效；
  不通过隐藏内容、拖慢文本输出或取消必要反馈换取指标。
- 平台：Chromium 自动化是已有证据，不替代 Safari/iPhone/VoiceOver 真机结果。
- 发布：禁止为消除失败放宽 golden 容差；解释并批准差异后更新基线。
  保留 Classic 回退和用户偏好，验证本地与 9000 实际返回的构建哈希。

## 七、建议立即执行的最小闭环

第一批不是继续全局调透明度，而是固定同一版本的 390px 明暗聊天、机器人
列表及一个 Sheet，完成逐张审阅，同时归因两项 Liquid golden 差异。
随后锁定设计规则，推进整页收敛；聊天真实组合交互作为独立发布门槛。

开始视觉定稿前最有价值的补充是用户认可的目标系统截图/录屏与目标 iPhone
型号。没有这些仍可做跨端品质优化，但不得据此宣布特定 iOS 版本还原完成。

## 八、深入诊断：差距来源与设计取舍

以下区分代码事实和待视觉确认的假设，避免将推测当作线上缺陷。

| 差距 | 已核对事实 | 设计影响 / 下一步 |
| --- | --- | --- |
| 光学表现 | GlassSurface 使用 BackdropFilter、渐变染色与绘制高光，没有折射采样 | 能表现磨砂与悬浮，但不能等同原生光学效果。先提升层级与透景，仅在必要时另立 shader 实验 |
| 三种材质辨识 | navigation/control 的底部 alpha 都为 .72，深色统一至少 .78；主要还有顶部 alpha 与 sigma 区别 | 暗色导航和控件可能视觉接近，需在滚动内容经过表面时对照，而不是直接降低所有透明度 |
| 全局参数影响大 | 多页共用 GlassSurface；已抑制祖先内重复 blur/tint | 一处调整会影响大量页面。先建立导航、输入框、Sheet 三个受控样例，再迁移配方 |
| 信息层级 | Bot 已有统一概览、状态、管理、新建和群组操作 | 合并工作无需重做；重点审查概览和多按钮是否挤占列表首屏，主次操作是否明确 |
| 静态与动态脱节 | 滚动已有 reading/following/restoringOlder 等阶段和 epoch 隔离 | 结构存在不代表组合场景可靠。验收应包含分页时继续拖动、图片变化、流式更新和会话切换 |
| 视觉基线未闭环 | 两项 Liquid 预览 golden 仍失败；画廊未批准 | 需要逐项解释布局和像素变化，不是重生成基线或累积截图数量 |
| 跨平台品质未知 | Web/iOS 共用 Flutter 材质；当前缺少 iPhone/Safari 实测 | 系统键盘、安全区、返回手势、动态文字和玻璃合成开销必须列为交付门槛 |

推荐以“跨端一致、接近 Liquid Glass 设计语言”为主线。不要把聊天正文、
每张任务卡和每行设置都玻璃化：背景缺少可透视内容时，增加 blur 无法产生
更强的空间感，反而增加灰雾和渲染成本。内容负责清晰，玻璃负责操作层级。

### 具体展示决策

- 聊天：固定正文起始线和最大阅读宽度；工具/审批与正文共享网格，
  不要求不同角色同宽。工具默认摘要、按需展开；审批保留风险与作用范围。
- Bot：名称与头像占稳定列，副标题优先展示用途；诊断移入展开区域。
  新建、管理、群组按使用频率确定主次，低频操作可收进管理，但保留可发现性。
- 任务：优先显示标题与状态；其余字段渐进呈现，避免一张卡同时突出所有标签。
  看板拖拽必须保留菜单/键盘替代操作，不能依赖精细触控。
- 更多：优先列表分组而非多层大卡；统一分隔线起点、尾部辅助信息和箭头。
  连接状态、错误和危险操作使用语义色，其余避免无意义的多色图标底块。
- 浮层：手机长内容使用可滚动 Sheet，短确认使用 Dialog；键盘出现后主操作
  仍可达。打开、关闭、返回和未保存保护遵守相同约定。
- 动效：复用现有 120ms 按压、240ms 展开作为候选，不作为 Apple 标准；
  高频流式文字不逐 token 播入场动画。减少动画时保持状态反馈。

### 实施管理与风险控制

每个改造项按“问题证据 → 设计决定 → 组件修改 → 整页复核 → 交互验证”
闭环记录，关联文件、场景与构建身份。代码完成、自动测试完成、视觉批准、
设备通过分别记录，不能只用一个完成勾选。

建议首批只锁定 390px 明暗聊天、Bot 和一个打开的 Sheet；以同一数据和
版本进行比较，明确保留/修改意见后再扩展任务与更多。组件迁移按页面拆分，
保留 Classic 与用户偏好。未审阅的 golden 不更新；未取得真机数据不填写
还原度或性能通过结论。当前不建议引入全屏折射 shader 或重写原生 UI，
它们属于额外技术路线，需另行评估成本、兼容性与可访问性。
